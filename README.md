# ShopEase Product Service

An independent Product Management microservice for the ShopEase e-commerce platform. It exposes REST APIs to create, retrieve, update and delete products, validates every request with Pydantic, and runs inside a Docker container.

Products are stored in memory, so data is lost when the application or container restarts. MySQL integration is covered in a separate task.

## Technology Stack

| Area | Tools |
|---|---|
| Backend | Python 3.11+, FastAPI, Uvicorn, Pydantic |
| Containerization | Docker, Dockerfile, Docker CLI |
| Testing | Swagger UI, Postman |
| Version control | Git, GitHub |

## Project Structure

```

├── app/
│   ├── main.py                    # creates the FastAPI app, registers routers and exception handlers

│   ├── models/
│   │   └── product_model.py       # Product data structure and status enum
│   ├── services/
│   │   └── product_service.py     # business logic and in-memory storage
│   └── config/
│       └── settings.py            # application configuration
├── Dockerfile
├── .dockerignore
├── requirements.txt
├── .env
└── README.md
```

A `.gitignore` file is also included so the virtual environment and cache files are not pushed to GitHub.

## Installation

Requirements: Python 3.11 or higher, Git, and Docker Desktop (for the container steps).

```powershell
python --version

python -m venv venv
venv\Scripts\activate

pip install -r requirements.txt
pip list
```

On macOS or Linux, activate with `source venv/bin/activate`.

## Run Locally

From the project root (the folder that contains `app/`):

```powershell
uvicorn app.main:app --reload --port 8003
```

Open http://localhost:8003/docs for Swagger UI.

## Run with Docker

Build the image:

```powershell
docker build -t shopease-product-service .
docker images
```

Run the container:

```powershell
docker run -d --name shopease-product-container -p 8003:8003 shopease-product-service
docker ps
docker logs shopease-product-container
```

Open http://localhost:8003/docs to confirm Swagger UI is served by the container.

Stop, restart and remove the container:

```powershell
docker stop shopease-product-container
docker start shopease-product-container
docker rm -f shopease-product-container
```

Port mapping `8003:8003` means host port 8003 forwards to container port 8003.

## Configuration

Settings are read from `.env` (see `app/config/settings.py` for defaults). The `.env` file is excluded from the Docker image by `.dockerignore`, so the container uses the same values as the defaults in `settings.py`. Never put passwords or API keys in `.env` if it is pushed to GitHub.

| Variable | Default | Purpose |
|---|---|---|
| APP_NAME | ShopEase Product Service | Name shown in Swagger UI |
| APP_VERSION | 1.0.0 | API version |
| DEBUG | false | FastAPI debug mode |
| DEFAULT_PAGE_LIMIT | 10 | Default `limit` for the list endpoint |
| MAX_PAGE_LIMIT | 100 | Maximum allowed `limit` |

## API Endpoints

Base URL: `http://localhost:8003`

| Method | Endpoint | Description | Success | Errors |
|---|---|---|---|---|
| POST | /api/products/ | Create a product | 201 | 400, 422 |
| GET | /api/products/ | List products (`category`, `skip`, `limit`) | 200 | 422 |
| GET | /api/products/{product_id} | Get a product by ID | 200 | 400, 404, 422 |
| PUT | /api/products/{product_id} | Update a product | 200 | 400, 404, 422 |
| DELETE | /api/products/{product_id} | Delete a product | 204 | 400, 404, 422 |
| GET | /health | Service health check | 200 | |

### Product fields

| Field | Rules |
|---|---|
| name | required, 1-100 characters, not blank, must contain letters or numbers |
| description | optional, up to 500 characters, blank text is stored as null |
| price | required, greater than 0 (zero and negative values rejected), rounded to 2 decimals |
| stock_quantity | required, integer, 0 or more |
| category | required, 2-50 characters, starts with a letter |
| status | `Active` or `Inactive` (default `Active`) |
| id | generated by the service |
| created_date | generated by the service |

### Create product

```
POST /api/products/
{
  "name": "Wireless Mouse",
  "description": "2.4 GHz ergonomic wireless mouse",
  "price": 799.0,
  "stock_quantity": 50,
  "category": "Electronics",
  "status": "Active"
}
```

Response `201 Created`:

```
{
  "name": "Wireless Mouse",
  "description": "2.4 GHz ergonomic wireless mouse",
  "price": 799.0,
  "stock_quantity": 50,
  "category": "Electronics",
  "status": "Active",
  "id": 1,
  "created_date": "2026-11-02T10:30:15.123456"
}
```

### List products

```
GET /api/products/?category=Electronics&skip=0&limit=10
```

Category matching ignores upper/lower case. An empty list `[]` is returned when nothing matches.

### Error format

Every error uses the same structure.

```
404 Not Found
{
  "status_code": 404,
  "error": "Not Found",
  "message": "Product with ID 99 not found"
}
```

```
422 Validation Error
{
  "status_code": 422,
  "error": "Validation Error",
  "message": "Invalid request data",
  "details": [
    { "field": "price", "message": "Input should be greater than 0" }
  ]
}
```

| Status | When |
|---|---|
| 200 | Successful request |
| 201 | Product created |
| 204 | Product deleted |
| 400 | Invalid JSON body, product ID of 0 or less, duplicate product ID |
| 404 | Product or route not found |
| 422 | Validation error (missing fields, wrong types, rule violations, non-numeric ID) |
| 500 | Unexpected server error (details are only written to the server log) |

## Testing

Start the app (locally or in Docker) and use Swagger UI at `/docs` or Postman.

| # | Scenario | Request | Expected |
|---|---|---|---|
| 1 | Create with valid data | POST /api/products/ with the sample body | 201 and the product with `id` 1 |
| 2 | Empty name | `"name": "   "` | 422, "Product name must not be empty" |
| 3 | Negative price | `"price": -5` | 422, price must be greater than 0 |
| 4 | Negative stock | `"stock_quantity": -1` | 422, stock must be 0 or more |
| 5 | Get all products | GET /api/products/ | 200 and a list |
| 6 | Get by valid ID | GET /api/products/1 | 200 and the product |
| 7 | Get by invalid ID | GET /api/products/99 | 404, "Product with ID 99 not found" |
| 8 | Update a product | PUT /api/products/1 with a full body | 200 and the updated product |
| 9 | Delete a product | DELETE /api/products/1 | 204 with no body |
| 10 | Get the deleted product | GET /api/products/1 | 404 |
| 11 | Category filter | GET /api/products/?category=Electronics | 200, only Electronics products |
| 12 | Pagination | GET /api/products/?skip=1&limit=1 | 200, one product |

Extra checks: `price` as `0`, a missing `category`, `status` set to `Deleted`, product ID `0` (400), product ID `abc` (422), and a broken JSON body (400).

After testing, run `docker logs shopease-product-container` and confirm there are no unexpected errors.

## Docker Instructions Explained

| Instruction | Why it is needed |
|---|---|
| `FROM python:3.11-slim` | Base image with Python 3.11 and a small size |
| `WORKDIR /app` | Folder inside the container where the app lives |
| `COPY requirements.txt .` | Copies only the dependency list first so Docker can cache the install step |
| `RUN pip install --no-cache-dir -r requirements.txt` | Installs the dependencies into the image |
| `COPY . .` | Copies the application source code |
| `EXPOSE 8003` | Documents the port the app listens on |
| `CMD [...]` | Starts Uvicorn on `0.0.0.0:8003` so it is reachable from outside the container |
